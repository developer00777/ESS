Foundation

One system for every ESS surface.

ESS is a brand skin on the shared multi-brand skeleton: spacing, type scale, elevation and motion are inherited, the teal identity is ours. Every colour, size and radius below is a token — change the token, every screen follows.

Fixed

The two-slab dashboard

A dark column beside a white column read as two apps. Dark is now one horizontal band at the top of the page only.

Fixed

Random card surfaces

Mint, white and dark were used interchangeably. Now four named surface roles, each with a rule for when it applies.

Fixed

Hand-rolled rows

Attendance, roster and policies each invented their own grid. One table pattern now covers all three.

Fixed

Flat hierarchy

Everything sat between 0.8–0.95rem. The scale now spans 11 → 40px with one role per step.

Surfaces

02

Four roles. Every panel in the portal maps to exactly one — that rule is what removes the mint/white/dark ambiguity.

canvas --ess-canvas

The page. Never used for a card.

surface --ess-surface

Default card, table, panel. 1px border, no shadow.

sunken --ess-sunken

Inset inside a surface: table head, meta, empty states.

inverse --ess-inverse

Nav rail and one hero band. Nothing else.

Don't

Split the page into a dark column and a light column. The eye reads two unrelated products.

Do

One dark band across the top, light content below it. Dark becomes emphasis, not a region.

Grouped by ownership

The flat 5–7 item list gains two group labels — Me and Manage — so a team lead can tell personal actions from managerial ones at a glance.

Pending approvals and open requests are surfaced as a pill on the nav item, so the dashboard is no longer the only place they appear.

Rules & migration

07
Do
Reference tokens: var(--ess-surface), never #fff. Start every card at border-only elevation; add shadow only when it floats. Give every list an empty state and a skeleton before shipping it. Use tabular numerals for days, times and balances. Keep one primary action per screen region.
Don't
Introduce a new grey, teal or radius — add a token or reuse one. Put dark cards inside a dark panel (the old stat grid). Build a new row layout per page; extend the table pattern. Use backdrop blur or decorative gradients. Ship a size between the eight type steps.
Migration into the SvelteKit app
1 · Tokens

Drop ess-tokens.css in src/lib/styles/ and import it first in app.css. Old --color-* names can alias to the new ones during transition.

2 · Components

Replace the component block of app.css with ess-components.css. .btn → .ess-btn, .card → .ess-card.

3 · Rewire

StatCard, StepTracker and SidebarNav lose their scoped colour rules and use tokens. Attendance, Team and Policies share one Table component.

4 · Dark mode

Set data-ess-theme on <html> from a user preference. No component changes needed.
